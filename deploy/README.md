# Перенос сайта на сервер с ISPmanager (Ubuntu, MySQL, PHP)

## Что подготовлено
- `mysql_schema.sql` — структура таблиц (продукция, услуги, заявки) + вся текущая продукция и услуги
- `api/config.php`, `api/products.php`, `api/services.php`, `api/leads.php` — PHP-скрипты, отдающие данные и принимающие заявки
- `.htaccess` — чтобы прямые ссылки на страницы товаров/услуг открывались корректно
- `api.ts.for-own-server` — файл для замены src/lib/api.ts перед сборкой

## Шаги переноса

### 1. База данных
1. В ISPmanager: **Базы данных → Создать базу** (MySQL). Запишите имя базы, пользователя и пароль.
2. Откройте её через **phpMyAdmin** (кнопка рядом с базой в ISPmanager).
3. Импортируйте файл `mysql_schema.sql` — вкладка **Импорт**. Создастся продукция, услуги и таблица заявок `leads`.

### 2. Получение готового сайта — два варианта

**Вариант А (проще, рекомендуется).** В poehali.dev нажмите **Скачать → Скачать билд**.
Скачается архив с уже готовыми статическими файлами (index.html, CSS, JS) — их не нужно
собирать самостоятельно. Распакуйте архив, внутри будут файлы для загрузки на сервер.
⚠️ В этом варианте сайт по умолчанию продолжит обращаться к базе на poehali.dev.
Чтобы он ходил к вашей MySQL через PHP-скрипты — понадобится вариант Б.

**Вариант Б (чтобы сайт работал с вашей MySQL базой).**
1. В poehali.dev нажмите **Скачать → Подключить GitHub** (или **Скачать код**).
2. Склонируйте/скачайте репозиторий себе на компьютер.
3. Замените содержимое `src/lib/api.ts` содержимым файла `deploy/api.ts.for-own-server`.
4. В корне проекта выполните:
   ```
   npm install
   npm run build
   ```
   Появится папка `dist` — это и есть готовый сайт, уже настроенный на ваш PHP+MySQL.

   ⚠️ **Если сервер на CentOS 7:** там нельзя напрямую поставить Node.js 20
   (нужна версия glibc новее той, что есть в CentOS 7). Используйте сборку через
   Docker — см. раздел «Сборка на CentOS 7» ниже, шаги 3-4 не нужны, скрипт
   `build-on-centos7.sh` сделает их сам.

### 3. Загрузка на сервер
1. В ISPmanager откройте **Файловый менеджер** для вашего домена.
2. Загрузите содержимое папки `dist` (не саму папку, а файлы внутри неё — из варианта А или Б) в корень сайта (обычно `public_html` или `www`).
3. Загрузите файл `deploy/.htaccess` в тот же корень сайта.
4. Создайте папку `api` в корне сайта и загрузите туда `products.php`, `services.php`, `leads.php`, `config.php`.

### 4. Настройка подключения к базе и почты
1. Откройте `api/config.php` через файловый менеджер ISPmanager (редактирование файла).
2. Впишите имя базы, пользователя и пароль, которые получили в шаге 1.
3. В строке `LEADS_EMAIL_TO` укажите почту, на которую должны приходить заявки с формы.
4. Сохраните.

### 5. Проверка
Откройте в браузере:
- `https://ваш-домен.ру/api/products.php` — должен вернуться список товаров в формате JSON
- `https://ваш-домен.ру/api/services.php` — список услуг
- `https://ваш-домен.ру/catalog` — страница каталога на сайте
- На сайте откройте раздел «Контакты» и отправьте тестовую заявку — она должна сохраниться
  в таблицу `leads` вашей базы и прийти на почту (если на сервере включена функция `mail()`,
  уточните у поддержки хостинга при необходимости)

Если что-то не работает — пришлите мне текст ошибки, разберём вместе.

## Настройка Nginx (Ubuntu)

Подготовлен готовый конфиг `nginx.conf.example` — обеспечивает SPA-роутинг
(прямые ссылки на страницы каталога/услуг) и передачу `/api/*.php` в PHP-FPM.

1. Скопируйте конфиг и подставьте свои значения (домен, путь к `public`, версия PHP-FPM):
   ```
   sudo cp deploy/nginx.conf.example /etc/nginx/sites-available/ваш-сайт
   sudo nano /etc/nginx/sites-available/ваш-сайт
   ```
   Версию PHP-FPM можно проверить командой `ls /run/php/`.
2. Включите сайт и перезапустите Nginx:
   ```
   sudo ln -s /etc/nginx/sites-available/ваш-сайт /etc/nginx/sites-enabled/
   sudo nginx -t
   sudo systemctl reload nginx
   ```
3. Для HTTPS используйте Certbot:
   ```
   sudo apt install -y certbot python3-certbot-nginx
   sudo certbot --nginx -d ваш-домен.ру -d www.ваш-домен.ру
   ```

## Сборка на CentOS 7 (через Docker)

CentOS 7 использует старую версию glibc, поэтому Node.js 20 туда напрямую не ставится.
Решение — собрать сайт внутри Docker-контейнера с нужной версией Node, а раздавать
готовые файлы обычным Apache/Nginx на сервере (Docker нужен только на этапе сборки).

Подготовлены: `Dockerfile.build` (описывает сборочный контейнер) и `build-on-centos7.sh`
(автоматический скрипт: ставит Docker при необходимости, собирает сайт, копирует файлы).

1. На сервере: `git clone` вашего репозитория (см. шаг 2, вариант Б, пункт 1-2 выше).
2. Откройте `deploy/build-on-centos7.sh` и поправьте переменную `SITE_DIR` — путь,
   куда веб-сервер смотрит как на корень сайта (в ISPmanager обычно вида
   `/var/www/www-root/data/www/ваш-домен.ру`).
3. Выполните:
   ```
   chmod +x deploy/build-on-centos7.sh
   ./deploy/build-on-centos7.sh
   ```
4. Дальше — шаги 4 и 5 из раздела выше (настройка `api/config.php` и проверка).

При обновлении сайта в будущем: `git pull`, затем снова запустить
`./deploy/build-on-centos7.sh` — файлы на сервере обновятся автоматически.

## Примечание про почту
Функция `mail()` в PHP работает не на всех хостингах "из коробки" — иногда письма
попадают в спам или не отправляются вовсе. Если заявки не будут приходить на почту,
скажите — настроим отправку через SMTP вашего почтового ящика вместо `mail()`.
